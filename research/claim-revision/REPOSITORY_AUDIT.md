# Claim Revision Proposal v0.12 — pre-code authority audit

Baseline bb66cc1d48524e440ffc678a3d77e75df1802bf6, clean before work; pushed to origin/main and independently verified before implementation. Production upstream push remains disabled; pre-push hook and check-dev-isolation PASS. Existing history is immutable.

1. **Authoritative write path:** `research/memory/store.js` ResearchMemory.createClaim/reviseClaim → private #writeRevision → SQLiteBackend.append inside an IMMEDIATE transaction. correctEvidence can explicitly atomically append corrections and reviewer-supplied revisions. markStale explicitly appends stale revisions. No model writer exists. Proposal code must never call these paths.
2. **Identity:** memory identity `{id,subjectId,createdAt}`. Existing v0.1 Claim IDs are retained, not regenerated when beliefs change.
3. **Revision state:** full Claim snapshot (statement/category/status/confidence/method/supportingEvidenceIds/counterEvidenceIds/timestamps), sequential version, previousRevisionId, effectiveAt, createdAt, revisionReason, note, staleEvaluation. ID is `CLAIM_ID:vN`. Exact base revision and payload hashes are necessary to detect stale proposals.
4. **Reason:** finite authoritative initial_ingest/new_supporting_evidence/new_counter_evidence/evidence_corrected/stale_evidence/manual_review/rule_change plus note. Proposal reasoning uses its own taxonomy, never silently invokes a revision reason or writer.
5. **Additive boundary:** read-only Memory/Admission SQLite snapshot; independent external Proposal SQLite with immutable proposals and review events. Model receives C1/R1/E1… aliases only. A PASS proposal is pending; an accepted review does not update Memory. No changes to ResearchMemory authority/storage version.
6. **Provenance:** revision links → support/counter Evidence → Source. Admission review independently binds resultingEvidenceId → Candidate/snapshot Chunk/Document/Source and validation. Grounded support provenance is available in Candidate metadata when present. Historical v0.1 reviewed imports can lack Admission reviews; these must NOT automatically count as Accepted Evidence for this feature. Require an actual accepted Admission review. system_test Admission remains explicitly synthetic/trusted test capability, not human review.
7. **Time:** observedAt is observation, documentDate publication, Memory envelope createdAt knowledge ingestion. Audit requires createdAt/effectiveAt ≤ asOf; Admission recordedAt/acceptedAt also ≤ asOf. Public availableAt cannot be future. Unknown public availability is permitted only in Audit. Replay asks theoretical public knowledge and must not reuse Audit ingestion cutoffs as if backdated; this stage explicitly supports Audit only and rejects Replay. Corrections are journal events; superseded new Evidence cannot support a fresh proposal. Old replaced references can be shown as context only. Effective times cannot regress, future Evidence must not influence past knowledge. Date-only queries are UTC end-of-day.

As-of reads use highest visible numbered revision, late entries do not appear in earlier audit queries. Diff compares belief fields/status/confidence/reference sets, not reason timestamps; status priority controls strengthened/weakened. These comparison ranks are not impact classifications or investment scores.

Confidence in Claim schema is 0–1; buildClaims inherits weakest supporting extraction confidence. Manual reviseClaim accepts reviewer confidence, but no unified authoritative confidence-update rule exists. v0.12 suggests increase/decrease/unchanged only, never a fabricated probability.
