# Evidence Admission v0.4 pre-code audit

Confirmed clean HEAD/origin 19871f6. Reviewed v0.1 Source/Evidence/Claim schemas and normalization, v0.2 backend/immutable Evidence/revisions/corrections/as-of/provenance, v0.3 actual Candidate/Document/Chunk schemas, citation reparse and temporal cutoff, CLI/eval/benchmark, CI and previous delivery reports. Baseline 109+25+49+49 tests passed. Dev isolation/hook/remotes unchanged.

Actual Candidate fields include queryId, quote/locator, retrieval method/rank, temporal context and hashes, but proposedCategory/proposedRawValue are null. It has no normalized fact, reviewer or admission lifecycle. validationStatus is citation status, not review decision. Source/Evidence schemas reject unknown fields; immutable facts cannot receive candidateId/acceptedAt in place.

Decision before coding: add independent immutable Review/admission relations in the same v0.2 Memory database, lazily initialized through a narrow backend participant API. Evidence+Review then share the existing synchronous transaction/savepoints, avoiding separate-store partial commits. Preserve records table/user_version=2, all Source/Evidence contracts and existing domain logic. Retrieval index and ranking/parser/ground truth remain unchanged.

Acceptance requires an explicit expected Candidate hash, human identity (system_test only via an explicitly test-enabled programmatic constructor), reason/note and reviewed fact mapping or pure exact quotation. Quote is never edited. Revalidate twice and compare Candidate/Chunk/Document/Source snapshots inside a Retrieval read transaction and Memory write transaction; copy immutable passage/provenance snapshots into Review. Fail closed on content/temporal changes. Atomic transactions cannot lock an external raw file; final reparse/hash checks and reviewed-byte snapshots identify what was admitted, while later byte changes invalidate future admission rather than rewrite history.

Duplicate policy: normalized fact/Source/exact quote/canonical locator key for new admissions, independent of query/reviewer/confidence. Existing accepted facts require matching Source/page, explicit semantic fact fields and exact quoted raw-value presence, never merely a similar retrieval score. Explicit supplied existingEvidenceId must match; ambiguous matches reject. Original existing Evidence stays unchanged. Review lineage stores scoped availableAt, candidateCreatedAt, reviewedAt and acceptedAt separately. Re-review requires explicitly superseding the latest event; rejection never deletes Evidence or reverses an old acceptance.
