## 摘要

FlowCredit 已从「纯静态演示站」阶段推进到「方案定型、工具链就位、等待真跑验证」阶段，定位从 AI 原生企业的链上可验证风控演示，演进为基于 DeepSeek Harness（dsh）的 Web3 与数字金融 AI 信用风控智能平台。核心闭环分为真实可行性三层：展示层与规则层已实证运行；AI 推理轨（dsh）P0 冒烟与离线账本 v1 已实证运行；数据接入与违约校准是真正的长线瓶颈，暂以演示口径推进。

### 1.5.1 dsh 集成：离线评估账本 v1（真实 LLM 推理）

- 环境：`agent/`（独立于仓库，含 .env 600 权限与 .gitignore），dsh 0.1.2-rc.1 + Node 22.23.2，模型 deepseek-chat，路由 api.deepseek.com/v1。
- 契约：五锚权重与演示站一致（25/25/20/15/15），CCI = 1000 × Σ(权重 × 锚分)，硬红旗强制否决；输出严格 JSON（锚分 + 证据引用 + 裁决 + 推理轨迹）。
- 实测结果（与演示基线对照）：

| 指标 | Healthy（演示基线） | Healthy（AI 实测） | Sybil（演示基线） | Sybil（AI 实测） |
| --- | --- | --- | --- | --- |
| CCI | 795 | 834 | 320 | 15 |
| PD | 2.3% | 3.0% | 85.0% | 85.0% |
| 等级/裁决 | A / approve | A / approve | F / reject | F / reject |
| 授信建议 | $20,000 | $20,000 | $0（红旗冻结） | $0（红旗冻结） |

- 结论：拦截决策、PD、授信额度与基线完全一致；CCI 同量级（healthy +5%）。Sybil 的 CCI 分歧源于打分口径——AI 对硬红旗锚记 0 分（否决即清零），演示引擎保留带内底分，属校准口径差异，非逻辑错误。
- 离线评估账本 v1（2026-09-05 上线）：`agent/run-audit.sh [healthy|watch|sybil|all]` 手动跑批 → 三主体 deepseek-chat 裁决 → `assets/js/ai-ledger.js` 原子入库 → autosync 提交推送（每次跑批 = 一条 git 审计凭证，历史全量可溯）。账本只存最新一轮，历史由提交链提供；`view-ai.js` 在工作台与报告页并置展示真实 AI 裁决卡（AI VERDICT · LIVE LLM，标注模型/时间/事实快照哈希），与 mock 基线并列但不参与任何派生计算。
- 账本 v1 首轮实测：healthy approve / CCI 866 / PD 2.5% / $20,000；watch watch / CCI 546 / PD 15% / $6,000；sybil reject / CCI 0 / PD 90% / $0 + 4 条硬红旗。watch 首跑曾误判全额否决，已在提示词补齐硬红旗量化门槛与 verdict 口径后修正。
- AI 口径注脚：红旗锚记零分生效、演示引擎保留带内底分，二者数值差异属口径差异；红线规则：AI 数据只向静态账本写入、只读展示，绝不改写 App.fn 公式与基线。

## 三、问题与场景清晰度

### 3.1 核心问题定义

AI 原生主体（GPU 算力商、API 服务商、链上主体）持有真实算力与现金流，但传统信贷与评级看不懂这些资产负债表，导致融资难、融资贵；放款方无法验证自报数据，空转、循环流水、女巫簇等欺诈在缺乏链上可信证据时难以及时识破。

FlowCredit 解决的问题是：**把「不可信的申报」变为「可核验的信用证据」，把「黑箱评分」变为「带完整证据链的评分」**，让每一分钱授信的决策、每一张审计报告都能追溯到原始数据、模型版本与推理轨迹。

### 3.2 目标用户

- 被审主体：AI 算力/推理服务商、DeFi 协议、数字资产相关企业——用证明换取更低成本的信用。
- 放款机构：链上借贷协议、中心化数字金融平台——需要可靠的贷前决策与贷后监控。
- 第三方复核与评级方：复用可重放凭证做独立复核；涉及法定审计的，由持牌审计师在平台外执行。
- 平台生态角色（远期）：独立评估节点（质押/惩罚机制）、投资者与监管观察员。

### 3.3 场景清单与清晰度分级
