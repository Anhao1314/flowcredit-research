FlowCredit 苹果式优化蓝图

2026-09-13 · 方法：定义本质 → 做减法 → 补断点（体验倒推、端到端、深层简洁、工艺、原型裁决）· 承接《实用性评估》《体验问题评估》两份结论 · B2B 强监管场景下对消费电子原则做了显式修正
核心主张：不要再加功能，先把产品收敛成一句话、一条路、一份能带走的报告。当前所有 P0 体验问题的共同根源是「演进史外露」——解法不是把旧东西折叠藏起来（表层极简），而是在底层消化复杂度：浏览器与服务端共用同一个确定性引擎、全产品只出一套结论。北极星只有一个：从打开到看到第一份可信结论的时间。

一、重写本质：先回答用户要完成什么任务

现状定义（能力/参数罗列）

「Risk Intelligence API for AI-native economic actors」「Connect compute, cash flow and on-chain activity」「Evidence → Risk → Action」。

问题：是工程语言与愿景清单，遮住产品名后脑中没有具体画面；「Connect / on-chain」还承诺了不存在的能力。

重写后（用户任务、有画面、无参数）

把你自己的经营数字，变成一份敢直接递给交易对手的风险结论——五分钟、零安装。

对标「1,000 songs in your pocket」：不强调引擎/版本/API，而强调「一份拿得出手的结论」这个结果。完成任务后的情绪词定为 Confident（我知道结论怎么来的、我敢发出去），不是「惊艳」。

二、体验倒推：黄金路径 vs 现状路径

现状路径 · 情绪在「点运行」处坠底
0:00落地被「Connect 四源」抬高预期
0:30选路分叉新评估 / Legacy 并列，不知点哪
2:00+24 个空字段HHI、R/C 无释义，报错是字段 key

黄金路径 · 先看到成品，再换成自己的数据

被技术绑架的关键妥协点：评分只存在于 Node 侧车，于是访客被迫「自己起服务」。体验倒推的结论是反过来——把无外部依赖的 risk-core-v021.js 编译为浏览器可跑版本，让静态站自己出分；需要 DeepSeek 时才提示连接。这是整个蓝图的技术支点（见第五节 H1 原型）。

三、功能取舍表：逐个判定，不做「精简」空话

功能服务的核心任务判定理由 / 复杂度去向
确定性风险引擎产出唯一权威结论保留强化核心资产；强化方向是浏览器/服务端同一份代码，从底层消灭两套口径
三个示例案例让人看懂「成品长什么样」保留强化从「legacy 绕路」升级为默认开场：预填→自动出分→可编辑
requiredActions 补证清单把 null 翻译成下一步保留强化渐进披露的主引擎：先给有限结论，再告诉用户补什么能改变结论
错误分级文案 / 草稿保护 / consent异常路径的信任保留强化已高于平均，是要守住的工艺资产
v0.1 / Live v0.2.1 / Saved AI 三套结果—合并合并为一套 v0.2.1 主结果；AI 只解释不出第二个分；复杂度在引擎层消除，而非折叠藏起
audit/report 的三种环境布局—合并一套响应式布局，离线/在线只是「AI 能力有无」的状态差
抽取同意 / 解释同意合规授权合并共用同一同意组件但状态独立，不再共用 modelConsent
Local Merkle proof本地一致性留痕下沉二级结果页一行轻量入口，不与 Run 等权，不进工作流完成条件；措辞改「一致性校验」
HHI / R-C 序列 / evidence JSON / L0–L5 细节专家级增强下沉二级默认收起、自然路径可发现；最小 9 字段即可出 limited 结论
本机侧车连接（127.0.0.1）开发者用真实 AI下沉二级降为开发者入口；访客路径永不出现「起服务」死按钮
Stress 场景敏感度示意下沉二级改名 Scenario 放报告附录；不叫 Monitor
Demo Wallet / Sepolia 假连接无删除不支撑任何用户任务，只传递过时链上信号
Demo Account 页无删除假机构 + v0.1 残留；「我的评估」已由 Workspace 承担
Connect / on-chain / Monitor 措辞—删除承诺了不存在的能力，改为「Organize supplied evidence」式如实表述
L0–L5 的 350ms 假步进「计算表演」—删除主叙事真计算在浏览器内是毫秒级；步进只保留为「展开看分数由来」的解释动画，不再伪装计算过程

四、重定义后的 v1 边界

只做三件核心能力（默认对其余一切说不）

CORE 1
零安装出一份评估

浏览器内确定性引擎；示例默认开场，30 秒内看到完整成品结论。

CORE 2
引导式换成自己的数据

示例即模板、字段说人话、最小字段先出结论，补证清单引导增强。

CORE 3
一份带得走的报告

打印/PDF、JSON 快照导出与恢复，不依赖任何后端。

明确不做清单（每个「不做」都写明顶住的是什么诱惑）

  • 不做真实数据连接器——顶住「four sources connect」的叙事诱惑；v1 只接受用户提供的数据并如实标注证据等级（self-reported 封顶规则保留）。
  • 不出 PD / 预期损失 / 推荐额度数字——顶住「看起来像完整风控产品」的诱惑；校准完成前保持 null，绝不用 mock 的 2.3% / $20,000 填充界面。
  • 不做持续监控/周期重评——顶住 P3「Monitor」的诱惑；只做单期评估 + 场景附录，直到真有新数据回路再改名。
  • 不做钱包与链上交互——顶住旧定位惯性。
  • 不做多版本结果并存——顶住「所有历史演示都要能跑」的兼容诱惑；git 历史保留，用户界面只有一套。
  • 不做账户/登录体系——顶住产品模板惯性；External Alpha 阶段无此任务。
  • AI 不评分——顶住「AI 原生」名头的诱惑；AI 只做抽取与解释，评分权永远在确定性引擎。

五、端到端链条：自控关键断点，开放处做兜底

环节控制状态处理原则（B 端无法全链自控，故自控关键断点 + 开放处兜底）
首次打开必须自控零安装出分；不能把「起 Node 服务」甩给访客——这是当前最严重的出戏点
数据录入自控模板 / 开放格式表单、JSON、描述三种入口，校验与示例由我方兜底
评分完全自控浏览器与服务端共用同一份 risk-core，保证口径一致、结果可复现
证据真实性当前不受控不假装核验：证据等级封顶 + requiredActions 明示「自报」局限，而非用 Verified 对勾粉饰
AI 抽取/解释合作 · 可失败DeepSeek 不可用时静默降级为纯确定性（现有机制保留），任何路径都不因 AI 挂掉而断
报告交付自控打印/导出全部本地完成，不依赖后端、不依赖标签页存活
API 集成开放 · 文档兜底OpenAPI、错误码→处置表、真实 host 示例、配额与冷启动幂等说明

六、用原型裁决的三个关键假设（别开会，做出来看）

假设（按失败杀伤力排序）最小原型通过 / 否决标准时间
H1 risk-core 能在浏览器内跑，且与 Node 结果一致把 risk-core-v021.js 打包为 IIFE，静态站直接调用现有 contracts/固定演练用例（93.8/929/A 等）全部字节级一致即通过；否则保留侧车方案1 天 spike
H2「先看示例成品」优于「先填空表单」两版入口 A/B，3–5 人按脚本走查任务「5 分钟内得到评估并复述结论」：完成率与耗时显著占优才定为默认3 天
H3 决策者要「可带走」胜过「在线交互」上线打印/JSON 导出，访谈 3 个目标伙伴导出被实际使用、或访谈明确指向 PDF/快照；否则再议在线看板优先级1 周

七、决策机制：一个北极星 + 单一负责人

北极星指标：Time-to-first-credible-result —— 从打开页面到看到第一份完整评估的时间，目标 < 30 秒（示例路径）。
规则：任何新功能、新入口、新措辞，若增加这条时间或制造新的路径分叉，默认否决；黄金路径指定一名 DRI 对端到端体验负责，有权对「不够好」说不。数据用来排除错误选项，品味在剩余选项中裁决。

八、三阶段落地顺序（含仓库铁律约束）

0
减法周 · 都是可逆的「双向门」，快速做

删 Demo Wallet 与 Account 页；合并为一套结果/一套布局；清用户可见版本号碎片；Connect/on-chain/Monitor 措辞对齐；proof 降级、工作流完成与 proof 解绑。注意：app.js、view-landing.js 属 AGENTS.md 冻结区，须先按 §2 修改 AGENTS.md 写明解冻理由并出任务书，每步在 agent/ 跑完全套自检（syntax / discipline / isolation / node --test / verify-release）。

1
黄金路径（1–2 周）· 核心战役

H1 引擎浏览器化 spike 并落地；示例默认开场；表单渐进披露（最小 9 字段先出 limited 结论）；报告打印样式 + JSON 导出/导入；草稿由 sessionStorage 升 localStorage。里程碑：静态站双击打开，30 秒内看到一份完整、唯一、可导出的评估。

2
信任与深度（2–4 周）· 单向门慢做

字段人话化 + Fill with example + 错误 key→标签；术语体系统一（一套编号、Anchor 消歧）；DX 补 OpenAPI/错误码表/配额/冷启动说明。对外契约（flowcredit.api/v1 等版本标识、API 字段、冻结基线数值）是单向门，改动须在交付说明单列。

九、刻意保留、不要在减法中误伤的东西

  • 失败保留草稿、504/429/离线三态文案、模型调用前强制 consent——异常路径的工艺资产。
  • 报告模态的 section 导航、Esc、焦点陷阱、aria-modal 与 skip link、aria-live、prefers-reduced-motion——导出改造时在打印版与新版中延续。
  • 证据等级封顶、自报局限、「非审计意见」免责口径——这是合规红线，减法不能减掉诚实。
  • 确定性引擎的固定演练基线与版本标识纪律——内部收敛口径时，对外契约仍按流程变更。
方法依据：苹果产品设计十原则（本质定义 / 聚焦说不 / 体验倒推 / 端到端 / 深层简洁 / 工艺 / 人文 / 原型裁决 / 品味机制），并按 B 端强监管场景修正：证据与生态环节必须开放，以「自控评分与报告 + 开放处兜底」替代消费电子式全栈自研。本蓝图为产品方案，未改动任何代码；落地时遵守仓库 AGENTS.md 冻结区与自检流程。
