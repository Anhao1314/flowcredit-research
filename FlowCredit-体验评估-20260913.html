FlowCredit 用户体验评估

评估日期 2026-09-13 · 视角：两类用户的完整体验链路——① 打开演示站的访客（landing → workspace → ingest → audit → report → account）② 接入 API 的开发者 · 依据：逐行阅读 assets/js/* 全部视图与 docs/public-api-v1.md
一句话总判断：视觉与微观工艺（空状态、错误文案、焦点管理）在同类 demo 里属于上游，但用户要独自穿过四堵「迷宫墙」——双路径分叉、离线跑不通、三套结果并存、版本术语泄漏；而 B2B 风控产品最关键的最后一公里——把报告带走、发给决策人——是断的。问题不在审美，而在内部工程演进史被直接转嫁给了用户。

四、体验问题分级（每条含证据与第一步）

P0 · 挡住用户拿到第一次价值

P0E1 · 双路径分叉 + 离线墙：新用户主流程在演示环境跑不通
用户遭遇
Workspace 同时给「新评估」和「Legacy 示例」两条路；走新评估填完表单点 Run，得到一句「Local Agent required · 127.0.0.1:8787」。而 AGENTS.md 承诺「双击 index.html 以 file:// 离线可跑」——离线能跑的只有 legacy 路径，当前主推的 v0.3 路径必须自建 Node 侧车 + 16 位 API key。
证据
view-ai-live.js：file:// 协议直接置 FC_LIVE=false；view-ingest.js：非 LIVE 时 Run 旁常驻「Local Agent required」且 assessDraft 不存在即报错；intake-v03.js 浏览器端只做校验与 sessionStorage 草稿，不含评分引擎。
替代方案
给访客一条「零安装即得结果」的路：把 v0.2.1 确定性引擎编译为浏览器可跑的纯 JS（本就无外部依赖），静态站直接出分，需要 DeepSeek 抽取时再提示连侧车；开发者路径另入口。
第一步
在入口页检测 !FC_LIVE：主按钮变成「Try a live example（runs in your browser）」，把「Connect local agent」降为开发者次级链接；先消除死按钮，再评估引擎浏览器化。
P0E2 · 三套结果、三种页面布局：逼用户做版本考古
用户遭遇
同一主体在页面上同时出现规则 v0.1（CCI 795、PD 2.3%、额度 $20,000）、Live v0.2.1（CCI 929、PD 为 null）、Saved AI（834/866）三套数；audit 页在 live / 离线 / 自定义草稿三种环境下是三套布局，report 同理。用户无法回答最朴素的问题：「所以结论到底是什么？」
证据
view-audit.js 的 renderCustom / live / 离线三分支与「Two assessments, separate conclusions」提示；view-report.js 的 open() 与 openLiveReport() 是两份几乎独立的报告；data.js 冻结基线与 risk-core-v021.js 口径不同。
替代方案
只保留一套面向用户的结论与布局：v0.2.1 为唯一主结果；v0.1 收进默认折叠的「历史方法」附录（live 下已部分这么做，离线也要一致）；AI 只以「解释/问答」形态出现，不再并列第三个分数。
第一步
删掉用户可见处的版本号碎片（报告里的 rule v0.1 chip、账户页 Rule version v0.1），一个页面只出现一个 CCI。
P0E3 · 报告带不走：B2B 产品的最后一公里是断的
用户遭遇
「Open Full Report」是一个关掉就消失的全屏模态：没有打印、PDF、导出、分享链接；草稿只存 sessionStorage，关标签页/发链接给同事都看不到。风控报告的核心任务是「拿给另一个决策人看」，现在出不了浏览器标签页。
证据
view-report.js 报告渲染为 #layers 内 overlay，无任何导出入口；intake-v03.js 持久化用 sessionStorage（KEY = flowcredit.intake.v03），workspace 文案也写明「without being written to … a database」。
替代方案
加「Print / Save PDF」（打印样式表即可，零后端依赖）+「Export report JSON」+ 可导入恢复；草稿从 sessionStorage 升 localStorage 或导出文件，让「填一半明天继续」成立。
第一步
先给报告模态加 @media print 与打印按钮（工作量最小、价值最直接），再补 JSON 导出。

P1 · 明显损害核心体验

P1E4 · 表单按引擎字段设计，而不是按用户手里有什么数据设计
证据与遭遇
「Customer HHI」「Claimed valid rate」「R: Declared / C: Credible series」没有一句「这是什么、为什么要、去哪拿」；缺字段时报错直接显示 inputTokensM 这类字段 key（readinessHtml 渲染 item.field）；手动表单没有「用示例填一遍」按钮（示例只走 legacy 路径，不会预填新表单）。
替代方案
每个字段加一行人话说明与示例值；错误信息映射回字段中文/英文标签；表单顶部加「Fill with example」供边改边学；R/C、HHI、evidence JSON 这类高级项整体下沉折叠（部分已做，继续收口）。
第一步
先做「Fill with example」按钮 + 错误字段 key→label 映射，两处改动小、立刻降低挫败。
P1E5 · 动作层级错位，且「Verified ✓」过度授予信任
证据与遭遇
「Create local proof」与「Run assessment」同排等权重，且顶部工作流把 01 步完成态绑定到 proof（app.js：ingest 完成条件是 anchored），让用户以为打指纹是必经步骤——但它不影响任何分数。验证弹窗写「4-leaf Merkle proof verified locally ✓」，对非专家读起来像真实加密核验，小字才说只是本地一致性。
替代方案
proof 降为结果区一行轻量「本地指纹（可选，不影响评分）」；工作流完成只看评估是否跑通；弹窗措辞改「Internal consistency check passed（本地一致性校验）」，去掉对勾式信任符号。
第一步
把工作流进度的完成条件从 anchored 改为「draft confirmed / run complete」。
P1E6 · 旧定位残留持续制造认知噪音
证据与遭遇
Landing 写「Connect compute, cash flow and on-chain activity」（无连接能力）；Demo Account 页有假钱包连接、Sepolia test USDC、500ms 模拟连接（app.js toggleWallet），账户页本身没有任何真实任务；「Report & Monitor」的 Monitor 是约 2 秒预设动画，不是持续监控，也没有「新一期数据进来后变化」的回路。
替代方案
动词对齐能力：Connect → Organize supplied evidence；删除假钱包与空账户页（或并入「我的评估」）；Monitor 改名 Scenario，直到真有周期性重评再叫监控。
第一步
先删 Demo Wallet 控件与导航入口——它不支撑任何用户任务，只传递「这是个链上项目」的过时信号。

P2 · 打磨项

P2E7 · 术语体系三套并行
证据与动作
P1/P2/P3、01/02/03、L0–L5 三套编号并存；L3「Anchor Check」（同业对标）与 L5「Anchor」（Merkle 指纹）同名异义。统一为一套 01/02/03 主流程编号，L 层改名为 Normalize/Filter/Peer check/Score/Proof。
P2E8 · 同意状态与重渲染的小毛刺
证据与动作
抽取同意与解释同意共用 draft.modelConsent，在一个屏勾选、另一屏也被勾上——拆成两个独立同意位；表单每次 blur 全量重渲染（现有焦点保留逻辑可兜底，但滚动与折叠态应继续验证）。
P2E9 · DX 补齐清单
证据与动作
补 OpenAPI/Postman collection；curl 示例换成真实 host；公开限流配额与 Retry-After 语义；在幂等章节显式标注「免费档冷启动会清空内存幂等记录」；补一张错误码→处置表。

五、已经做对、要保留的工艺

  • 失败时保住用户劳动：504/429/服务不可用分别给不同文案，且明确「Your draft was preserved」（view-ingest.js）。
  • 模型调用先同意：抽取与解释都有显式 consent 勾选，并写明「model cannot score」。
  • 报告模态的无障碍工艺：section 导航、Esc 关闭、焦点陷阱与归还（focusDialog）、aria-modal/dialog。
  • 空状态不空：workspace 空列表、report 未评估都有说明与下一步 CTA（ui.pending）。
  • 全局健壮性：skip link、aria-current、aria-live、prefers-reduced-motion、动画中切页清 timer、视图渲染 try/catch fallback。
  • 克制的免责口径：关键决策点基本都有 demo/simulation 标注（问题主要在视觉层级，而非缺失）。

六、建议的整改顺序

1

第 1 周 · 拆掉迷宫墙：非 LIVE 访客默认走可跑通的示例路径、隐藏死按钮（E1）；清理用户可见版本号、一页只留一个 CCI（E2）。

2

第 1–2 周 · 打通最后一公里：报告打印/PDF + JSON 导出，草稿可跨标签页（E3）；工作流完成与 proof 解绑、验证弹窗改措辞（E5）。

3

第 2–3 周 · 降低填写摩擦：字段人话说明、Fill with example、错误 key→标签（E4）；删假钱包/空账户页、Landing 动词对齐能力、Monitor 改名（E6）。

4

第 4 周 · DX 与术语收口：OpenAPI、错误码表、配额文档、冷启动幂等说明（E9）；统一编号与 Anchor 命名（E7）。
